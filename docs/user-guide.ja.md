# A11yFix 利用者ガイド

**サービス URL:** https://www.geta11yfix.com  
**サポート:** support@geta11yfix.com  

A11yFix は、公開 Web ページのアクセシビリティ（WCAG）を自動検査し、AI による修正案・GitHub PR・進捗の証拠（バッジ／声明草案）・スコア監視までをつなぐツールです。  
**オーバーレイ型ウィジェットではありません。** コードと記録に残る成果物を重視します。

画面の表示言語は英語です。本資料では、画面上の英語表記を併記します。

---

## 1. できること（全体像）

| 機能 | 内容 |
|------|------|
| **Site scan / Single page** | sitemap から同一ホストのページを検査、または 1 URL だけ検査 |
| **AI Fix** | 違反箇所の HTML 修正案を生成。可能なら axe-core で再検証 |
| **GitHub PR** | 修正をリポジトリに Pull Request として作成（トークンは保存しません） |
| **History** | 過去のスキャン結果を見返し、再 Fix も可能 |
| **Badge** | ホスト最新スコアの埋め込み画像 |
| **Draft ACR** | 自動生成の適合声明**草案**（正式な VPAT ではありません） |
| **Monitoring** | 登録ホストを定期再チェックし、スコア低下時にメール通知 |

## 3. プランと枠（重要）

枠は **UTC の暦月**でリセットされます。  
**ページを 1 つ検査するたびにスキャン枠を 1 消費**します。

| プラン | サイト数 / 月 | ページスキャン / 月 | AI 修正 / 月 | サイトスキャン |
|--------|---------------|---------------------|--------------|----------------|
| **Free** | 3 | 15 | 15 | 発見最大 5 ページ（即時は最大 2、残りはキュー） |
| **Pro** ($29/月) | 3 | 1,000 | 1,000 | 発見最大 25（即時は最大 3） |
| **Agency** ($99) | ウェイトリスト | — | — | 要相談 |

補足:

- `example.com` / `example.org` / `example.net`（および www 付き）は **サイト枠を消費しません**（動作確認用）  
- Free / Pro のアップグレードは画面の **Upgrade to Pro**（Stripe）  
- Agency はウェイトリストから案内

## 4. スキャンのしかた

### 4.1 Site scan（推奨）

1. **Site scan (sitemap)** を選ぶ  
2. 公開 URL を入力（例: `https://your-site.com/`）  
3. **Scan site** を押す  
4. 同一ホストの `sitemap.xml` 等からページを発見し、先に数ページを検査  
5. 残りはバックグラウンドキューへ（日次処理）。結果に **queued** と出ることがあります  

### 4.2 Single page

1. **Single page** を選ぶ  
2. 1 つの URL を検査  

### 4.3 結果の見方

- **Score:** サイトスキャンでは成功したページのうち **最も低いスコア**（平均ではありません）  
- ページ一覧: 成功は Saved、失敗は理由（タイムアウト、ボット壁など）  
- 黄色い注意書き: Draft ACR は正式 VPAT ではない、バッジは適合証明ではない  

### 4.4 うまくいかないとき

| 症状 | 対処 |
|------|------|
| **BOT_CHECK** | 本番のボット対策ページを読んでいる可能性。ステージング URL や `https://example.com` で確認 |
| **HTTP 504 / timeout** | 一度再試行。重いサイトは **Single page** に切り替え |
| **SITE_LIMIT** | 今月すでに使ったホストを続けるか、example.com、または Upgrade |
| **QUOTA** | 月枠消化。来月まで待つか Upgrade |

## 5. AI 修正と GitHub PR

1. 違反（violation）の各ノードで **Fix with AI**  
2. 修正 HTML と説明が表示されます  
3. 検証ステータス:
   - **Verified / axe-clean** … サンドボックスでそのルールの違反が消えた  
   - **Not verified** … まだ残っている可能性。レビュー必須  
   - **Not checked** … ページ全体が必要なルールで単体検証不可  
4. **Open GitHub PR (axe-clean)** または **(review first)**  
5. 入力するもの:
   - Owner / Repo  
   - リポジトリ内のファイルパス  
   - GitHub の fine-grained PAT（Contents / Pull requests の書き込み）。**一度きりの送信で保存されません**  

AI 修正は提案です。本番反映前に必ず人間がレビューしてください。

## 7. Draft ACR（適合声明の草案）

1. 結果画面の **Open draft ACR (not a VPAT)**  
2. ブラウザで声明書が開きます。**Print / Save as PDF** で保存可能  

**必ず理解してほしいこと**

- axe-core による **自動検査の草案**です  
- **正式な VPAT® や監査人署名の ACR ではありません**  
- 調達・法務の最終提出物としては使えません（社内共有・たたき台向け）  
- キーボード操作やスクリーンリーダー確認など、手作業の評価は別途必要です  

---

## 8. 埋め込みバッジ

結果の **Embeddable badge** から HTML をコピーしてサイトに貼れます。

- 表示は **スコア**です。「WCAG 適合済み」の法的証明ではありません  
- URL 内の `token` は秘密情報として扱ってください  

---

## 9. スコア監視（Monitoring）

1. 結果の **Enable score monitoring**  
2. 通知先メールを確認し **Save monitor**  
3. Slack は任意。入れる場合は `https://hooks.slack.com/...` のみ有効（サイト URL は不可）  

動作の目安:

- 登録ホストを定期的に再チェック（スケジューラは日次。週次相当の間隔で due 判定）  
- **前回よりスコアが下がったとき**にメール（Resend）  
- チェック 1 回あたりスキャン枠を 1 消費します

## 13. よくある質問

**Q. これで ADA / 訴訟を防げますか？**  
A. 防げると保証するものではありません。自動検査と修正支援ツールです。法的助言ではありません。

**Q. サイト全体を一度に全部検査できますか？**  
A. sitemap から同一ホストを集めますが、サーバー時間の都合で即時は少数ページ、残りはキューです。巨大サイトの完全保証はありません。

**Q. ボットチェックで止まります**  
A. Cloudflare 等で人間確認が必要なページは、誤スコア防止のため意図的に止めます。ステージングや公開キャッシュ可能なページを試してください。

**Q. Free で十分ですか？**  
A. 体験・小規模確認向けです。継続的なリリース前チェックや多ページ運用は Pro を想定しています。
